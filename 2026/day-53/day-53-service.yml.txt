# Day 53 – Kubernetes Services

## 🎯 Objective

The goal of Day 53 was to understand how Kubernetes Services provide stable networking for Pods. Since Pod IP addresses are temporary and change whenever Pods restart, Services act as a stable networking layer that enables reliable communication and load balancing between applications.

---

# Why Kubernetes Services?

Pods are ephemeral by nature. Whenever a Pod is recreated, its IP address changes.

This creates two major challenges:

* Pod IPs are not permanent.
* Deployments run multiple Pods, making it difficult to know which Pod should receive traffic.

A Kubernetes Service solves these issues by providing:

* A stable virtual IP address (ClusterIP)
* Automatic load balancing across Pods
* Built-in DNS-based service discovery

# ClusterIP Service

ClusterIP is the default Service type.

Characteristics:

* Accessible only inside the Kubernetes cluster
* Provides a stable internal IP
* Supports service-to-service communication

Example:

```yaml id="a8z12r"
apiVersion: v1
kind: Service
metadata:
  name: web-app-clusterip
spec:
  type: ClusterIP
  selector:
    app: web-app
  ports:
  - port: 80
    targetPort: 80
```

Verified using:

```bash id="h3y1tp"
kubectl get services
kubectl run test-client --image=busybox --rm -it -- sh
wget -qO- http://web-app-clusterip
```

# Kubernetes DNS

Every Service automatically receives a DNS name.

Format:

```text id="kt72pm"
<service-name>.<namespace>.svc.cluster.local
```

Example:

```text id="qf7pw1"
web-app-clusterip.default.svc.cluster.local
```

DNS lookup:

```bash id="kfh73e"
nslookup web-app-clusterip
```

---

# NodePort Service

NodePort exposes the application on every Kubernetes node.

Characteristics:

* External access using Node IP
* Port range: 30000–32767
* Commonly used for development and testing

Example:

```yaml id="r9e4ux"
type: NodePort
nodePort: 30080
```

Access:

```text id="wz8jha"
http://<NodeIP>:30080
```

---

# LoadBalancer Service

LoadBalancer is designed for cloud environments.

Characteristics:

* Creates a cloud load balancer
* Assigns a public IP
* Used in production environments

Example:

```yaml id="z3jh9u"
type: LoadBalancer
```

On local clusters (Kind/Minikube), the External IP usually appears as:

```text id="0lsj5d"
<pending>
```

because no cloud provider exists to provision an external load balancer.

---

# Service Comparison

| Service Type | Accessible From | Common Use Case        |
| ------------ | --------------- | ---------------------- |
| ClusterIP    | Inside Cluster  | Internal communication |
| NodePort     | NodeIP:Port     | Development & Testing  |
| LoadBalancer | Public IP       | Production deployments |

---

# Kubernetes Endpoints

A Service routes traffic to Pods through Endpoints.

View Endpoints:

```bash id="s8v92r"
kubectl get endpoints
kubectl describe service web-app-clusterip
```

Endpoints automatically update whenever Pods are created or deleted.
