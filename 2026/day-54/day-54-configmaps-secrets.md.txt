# Day 54 – Kubernetes ConfigMaps and Secrets

## 🎯 Objective

The goal of Day 54 was to understand how Kubernetes manages application configuration using **ConfigMaps** and **Secrets**. Instead of hardcoding configuration values inside container images, Kubernetes allows applications to consume configuration dynamically through environment variables or mounted files.

---

# Why ConfigMaps and Secrets?

Applications require configuration such as:

* Application environment
* Feature flags
* Database URLs
* API keys
* Credentials

Embedding these values inside Docker images is not a good practice because every configuration change requires rebuilding the image.

Kubernetes solves this problem using:

* **ConfigMaps** → Store non-sensitive configuration.
* **Secrets** → Store sensitive information like passwords, tokens, and API keys.

---

# ConfigMaps

A ConfigMap stores application configuration in plain text.

Example values:

* APP_ENV=production
* APP_DEBUG=false
* APP_PORT=8080

Created using:

```bash id="7c2nka"
kubectl create configmap app-config \
--from-literal=APP_ENV=production \
--from-literal=APP_DEBUG=false \
--from-literal=APP_PORT=8080
```

Verified using:

```bash id="e8u4vz"
kubectl describe configmap app-config
kubectl get configmap app-config -o yaml
```

---

# ConfigMap from File

Created an Nginx configuration file and converted it into a ConfigMap.

```bash id="f0t8pk"
kubectl create configmap nginx-config \
--from-file=default.conf=default.conf
```

This approach is useful for storing complete configuration files.

---

# Using ConfigMaps

## Environment Variables

Injected configuration into a Pod using:

```yaml id="d1q8mr"
envFrom:
- configMapRef:
    name: app-config
```

Best suited for:

* Small key-value configuration
* Feature flags
* Application settings

---

## Volume Mount

Mounted an entire ConfigMap into a Pod.

```yaml id="v3l2gt"
volumeMounts:
- mountPath: /etc/nginx/conf.d
```

Best suited for:

* Nginx configuration
* Application configuration files
* JSON or YAML configuration

---

# Kubernetes Secrets

Secrets securely store sensitive information.

Created Secret:

```bash id="n5p7we"
kubectl create secret generic db-credentials \
--from-literal=DB_USER=admin \
--from-literal=DB_PASSWORD=s3cureP@ssw0rd
```

Viewed Secret:

```bash id="q2a6xy"
kubectl get secret db-credentials -o yaml
```

---

# Base64 Encoding

Secret values appear as Base64.

Decoded using:

```bash id="m4v9jc"
echo "<base64-value>" | base64 --decode
```

Important:

**Base64 is NOT encryption.**

It is simply an encoding format. Anyone with cluster access can decode it.

Real security comes from:

* RBAC
* Encryption at Rest
* Least Privilege Access

---

# Using Secrets in Pods

Secrets can be consumed in two ways.

### Environment Variable

```yaml id="k8f3db"
valueFrom:
  secretKeyRef:
    name: db-credentials
    key: DB_USER
```

### Volume Mount

```yaml id="h6u1sp"
volumes:
- secret:
    secretName: db-credentials
```

Mounted Secret files contain decoded plaintext values.

---

# ConfigMap Updates

Created a live ConfigMap.

Mounted it into a Pod.

Updated using:

```bash id="x7r5mn"
kubectl patch configmap live-config \
--type merge \
-p '{"data":{"message":"world"}}'
```

Observation:

* Volume-mounted ConfigMaps update automatically.
* Environment variables remain unchanged until the Pod is restarted.

---

# Environment Variables vs Volume Mounts

| Environment Variables          | Volume Mounts                |
| ------------------------------ | ---------------------------- |
| Simple key-value pairs         | Complete configuration files |
| Loaded only during Pod startup | Automatically updated        |
| Easy to consume                | Better for large configs     |
