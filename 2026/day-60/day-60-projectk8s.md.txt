# Day 60 – Kubernetes Capstone: Deploying StockLoom on Kubernetes

## Objective

Deploy the **StockLoom Inventory & Warehouse Management Platform** on Kubernetes using the concepts learned throughout Days 50–59.

---

# Project Overview

StockLoom is a production-ready Inventory & Warehouse Management platform built with:

- FastAPI
- NiceGUI
- PostgreSQL
- Docker
- GitHub Actions
- DevSecOps Pipeline

Instead of deploying the sample WordPress application, this capstone demonstrates deploying a real-world production-style application on Kubernetes.

# Architecture

```
                    Users
                      │
                      │
              NodePort Service
                      │
        ┌─────────────┴─────────────┐
        │                           │
 StockLoom Deployment (2 Replicas)
        │                           │
        └─────────────┬─────────────┘
                      │
                 ConfigMap
                      │
                  Kubernetes
                    Secret
                      │
               PostgreSQL Service
                      │
              PostgreSQL StatefulSet
                      │
               Persistent Volume
```

## PostgreSQL

Deployed using:

- StatefulSet

Features:

- Persistent Storage
- Stable DNS
- Stable Pod Identity

---

## StockLoom Backend

Deployed using:

Deployment

Features:

- 2 Replicas
- Self-Healing
- Rolling Updates
- Resource Requests
- Resource Limits

---

## Service

NodePort Service exposes StockLoom.

Example:

```
http://localhost:30080
```

---

## Persistent Storage

PVC attached to PostgreSQL.

Database remains available even after Pod recreation.

---

## Health Checks

Configured:

- Liveness Probe
- Readiness Probe

Ensures automatic recovery.

---

## Horizontal Pod Autoscaler

Configured:

- Minimum Replicas: 2
- Maximum Replicas: 10
- CPU Target: 50%

# Self-Healing Test

Deleted one StockLoom Pod.

Result:

- Deployment automatically recreated the Pod.
- Application remained available.

---

# Persistent Storage Test

Deleted PostgreSQL Pod.

Result:

- StatefulSet recreated the Pod.
- PVC retained database.
- Inventory data remained intact.
