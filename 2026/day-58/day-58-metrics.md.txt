# Day 58 – Kubernetes Metrics Server & Horizontal Pod Autoscaler (HPA)

## 🎯 Objective

The objective of Day 58 was to understand how Kubernetes automatically scales applications using the **Metrics Server** and **Horizontal Pod Autoscaler (HPA)** based on CPU utilization.

---

# Why Auto Scaling?

Application traffic is never constant.

During peak hours:

* More CPU is required.
* More Pods are needed.

During low traffic:

* Extra Pods waste resources.

Kubernetes solves this using the **Horizontal Pod Autoscaler (HPA)**.

---

# Metrics Server

The Metrics Server is a Kubernetes component that collects CPU and Memory usage from every node and Pod.

It enables commands such as:

```bash
kubectl top nodes
kubectl top pods
```

Without the Metrics Server:

* `kubectl top` doesn't work.
* HPA cannot make scaling decisions.

---

# Exploring Resource Usage

Used the following commands:

```bash
kubectl top nodes
kubectl top pods -A
kubectl top pods --sort-by=cpu
```

Observed:

* Node CPU Usage
* Node Memory Usage
* Pod Resource Consumption
* Highest CPU-consuming Pod

---

# Deployment with CPU Requests

Created a Deployment using the official HPA example image.

Configured:

```yaml
resources:
  requests:
    cpu: "200m"
```

CPU Requests are mandatory because HPA calculates utilization based on requested CPU.

---

# Horizontal Pod Autoscaler (HPA)

Created an HPA using:

```bash
kubectl autoscale deployment php-apache \
  --cpu-percent=50 \
  --min=1 \
  --max=10
```

Verified using:

```bash
kubectl get hpa
kubectl describe hpa
```

The HPA continuously monitored CPU utilization and adjusted replica count automatically.

---

# Load Testing

Generated continuous traffic using BusyBox:

```bash
kubectl run load-generator \
--image=busybox:1.36 \
--restart=Never \
-- /bin/sh -c \
"while true; do wget -q -O- http://php-apache; done"
```

Observation:

* CPU usage increased.
* HPA detected high utilization.
* Pod replicas increased automatically.

After stopping the load:

```bash
kubectl delete pod load-generator
```

Kubernetes gradually scaled the Deployment back down.

---

# HPA Scaling Formula

Kubernetes calculates desired replicas using:

```text
desiredReplicas =
ceil(
currentReplicas ×
(currentCPU / targetCPU)
)
```

Example:

Current Replicas = 2

Current CPU = 80%

Target CPU = 50%

Result:

```text
ceil(2 × 80/50) = 4 Replicas
```

---

# autoscaling/v1 vs autoscaling/v2

| autoscaling/v1            | autoscaling/v2               |
| ------------------------- | ---------------------------- |
| CPU Metrics Only          | CPU, Memory & Custom Metrics |
| Basic Scaling             | Advanced Scaling Policies    |
| No Behavior Configuration | Scale-up & Scale-down Rules  |
| Limited Features          | Production Ready             |

---

# Behavior Section

The **behavior** section in `autoscaling/v2` controls:

* Scale-up speed
* Scale-down delay
* Stabilization windows
* Number of Pods added or removed

This prevents unnecessary scaling fluctuations.
